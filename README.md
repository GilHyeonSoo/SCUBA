스킨스쿠버·프리다이빙 통합 플랫폼 앱 기획안

1. 서비스 개요

본 앱은 스쿠버다이빙과 프리다이빙을 즐기는 사용자를 위한 통합 다이빙 플랫폼을 목표로 합니다.

현재 다이빙 관련 서비스는 크게 다이빙 로그, 다이빙 샵/포인트 정보, 장비 판매, 커뮤니티 등으로 분산되어 있습니다. 이 앱은 이를 하나로 묶어 다음 흐름을 만드는 것이 핵심입니다.

다이빙 계획 → 버디 찾기 → 투어 참여 → 장비 준비 → 실제 다이빙 → 로그 기록 → 장비 관리 → 다음 다이빙

즉, 단순 커뮤니티가 아니라 다이버의 다이빙 생활 전체를 관리하는 플랫폼으로 설계합니다.

서비스 핵심 가치

“어디서, 누구와, 어떤 장비로 다이빙할지 결정하고, 다이빙 이후의 기록과 장비 관리까지 한 앱에서 해결한다.”

3. 버디 찾기 기능

기능 목적

다이빙을 계획하는 사용자가 자신의 주변 또는 특정 다이빙 지역에서 함께 다이빙할 사람을 찾을 수 있도록 하는 기능입니다.

레크리에이션 스쿠버다이빙에서는 버디 시스템이 기본적인 안전 원칙으로 사용됩니다. 다만 엄밀히 말하면 모든 경우에 반드시 2인 이상이어야 한다고 표현하는 것은 정확하지 않습니다. PADI에도 별도의 교육과 자격요건을 갖춘 Self-Reliant Diver 과정이 존재합니다. 따라서 앱 문구는 “다이빙은 반드시 둘 이상”보다는 “일반적인 레크리에이션 다이빙에서는 버디 다이빙을 기본 원칙으로 합니다” 정도가 적절합니다.  

기본 화면

버디 메뉴 진입 시 가장 먼저 세계지도 기반 화면이 표시됩니다.

사용자의 현재 위치가 지도 중심에 위치하며 주변 다이버를 표시합니다.

지도 확대/축소에 따라 검색 범위를 변경합니다.

다이빙 컴퓨터 제조사마다 통신 규격이 다르기 때문에 Bluetooth만 구현하면 모든 기기가 연결되는 구조가 아닙니다.

실제로 Suunto는 일부 D5/EON 계열을 Bluetooth로 자체 앱과 직접 동기화하지만, 다른 모델들은 SuuntoLink를 통해 동기화합니다. Garmin Dive 역시 Garmin 기기를 중심으로 동작하며 파일 가져오기에도 제약이 있습니다.  

따라서 첫 버전부터 “모든 다이빙 컴퓨터 직접 연결”을 목표로 하면 개발 난도가 크게 상승합니다.

15. 다이빙 컴퓨터 연동

여기가 전체 프로젝트에서 기술난도가 가장 높습니다.

구조는:

Dive Computer
↓ Bluetooth LE
React Native
↓
Native BLE Module
↓
Raw Data
↓
Parser
↓
Dive Log DB

입니다.

예:

Garmin
Suunto
Shearwater
Cressi
Mares
Oceanic

각 기기마다 프로토콜이 다를 수 있습니다.

그래서 앱 전체 구조에서 Bluetooth 코드를 별도 모듈로 분리해야 합니다.

/src
 /bluetooth
    /garmin
    /suunto
    /shearwater

처럼 설계하는 것이 좋습니다.

또는
개발 URL

로 PC 브라우저에서 확인할 수 있습니다.

React Native + Expo는 Web도 함께 지원할 수 있습니다.  

다만 최종 QA는 반드시

두 기기에서 해야 합니다.

21. 앱 업데이트 방식

개발 후에도 Expo 장점이 있습니다.

일부 JavaScript/리소스 수정은 OTA 업데이트 구조를 사용할 수 있습니다.

Expo Updates는 앱 실행 시 업데이트를 확인하고 내려받아 적용할 수 있는 구조를 제공합니다.  

예를 들어

버튼 위치 변경
텍스트 변경
UI 버그 수정

같은 업데이트는 경우에 따라 매번 전체 앱스토어 심사를 거치지 않고 배포할 수 있습니다.

단 네이티브 코드나 권한 변경 등은 새로운 앱 빌드가 필요합니다.
